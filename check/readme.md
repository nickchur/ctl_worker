# Инструменты тестирования и проверки (ctl/check)

Данная директория содержит инструменты и DAG'и для верификации работоспособности кастомных операторов и системных компонентов платформы.

## Состав

### [show_connections.py](show_connections.py)
**Аудит и группировка Airflow Connections.**

Выводит список всех подключений, сгруппированных по типу. Используется для быстрой проверки конфигурации secret backend.
*   **Кэширование**: Результаты сохраняются в Airflow Variable `local_connections`.
*   **Интеграция**: Служит источником данных для DAG'а `test_connections`.

### [test_connections.py](test_connections.py)
**Мониторинг и проверка всех Airflow Connections.**

DAG автоматически обнаруживает все подключения и проверяет их доступность.
*   **Kafka**: Многостадийная проверка SSL и TCP Ping для диагностики ошибок Firewall vs mTLS.
*   **mTLS диагностика**: Сообщает о недостающих сертификатах на воркерах.
*   **Стандартизация**: Статус пропущенных проверок помечается символом `☮️`.
*   **Отчетность**: Формирует сводную таблицу ✅/❌/☮️ в заметках DAG'а.

### [test_hrp_operators.py](test_hrp_operators.py)
**Исчерпывающий тестовый стенд для кастомных операторов (HRP Operators).**

Этот DAG предназначен для функционального и регрессионного тестирования операторов из пакета `hrp_operators`. Используется как обязательный этап валидации перед релизами и обновлением зависимостей Airflow.

#### Особенности реализации:
*   **Data Integrity**: Покрытие сложных типов данных, включая **Array (массивы)** в Postgres и ClickHouse.
*   **Quality Gate**: Тестовые таблицы создаются с полным описанием (COMMENT ON) для соответствия корпоративным стандартам качества.
*   **Валидация**: После каждой переливки выполняется автоматическая сверка количества строк и содержимого (включая проверку элементов массивов).
*   **Corner Cases**: Проверка обработки спецсимволов (`\n`, `\t`, `"`, `,`, `;`), NULL-значений и различных режимов сжатия (GZIP).
*   **Изоляция**: Полный цикл `Setup` -> `Test` -> `Cleanup` (удаление таблиц и файлов S3 даже при падении тестов).

#### Основные группы тестов:
1.  **pg_to_s3**: Выгрузка из Postgres в S3 с использованием `xstream_sanitize`.
2.  **s3_to_ch**: Загрузка из S3 в ClickHouse с валидацией массивов.
3.  **ch_to_s3**: Выгрузка из ClickHouse (Table, Query, Native).
4.  **db_to_db**: Переливки PG <-> CH, PG -> PG, CH -> PG.
5.  **s3_utils**: Проверка архивации и сверка хэш-сумм файлов.

## Индикаторы статусов

| Иконка | Статус | Описание |
|---|---|---|
| ✅ | Success | Проверка пройдена успешно |
| ❌ | Fail | Ошибка подключения или логики (AirflowFailException) |
| ☮️ | Skip | Проверка пропущена (например, нет нужной библиотеки) |
| ⏳ | Wait | Ожидание таймаута или события |

## Как запустить тесты

1.  Перейдите в Airflow UI.
2.  Найдите DAG `test_hrp_operators` (для операторов) или `test_connections` (для коннектов).
3.  Нажмите **Trigger DAG w/ config**.
4.  Для операторов: укажите целевые `conn_id` и бакет для тестов.
5.  Нажмите **Trigger**.

## Добавление новых тестов

При создании нового оператора в `hrp_operators`:
1.  Зарегистрируйте оператор в `sber_app_dataplatform_etl_core.hrp_operators.__init__`.
2.  Добавьте импорт и таск в соответствующую `task_group` внутри `test_hrp_operators.py`.
3.  Добавьте логику валидации данных после выполнения оператора.
4.  Убедитесь, что `cleanup` корректно удаляет все созданные артефакты.
