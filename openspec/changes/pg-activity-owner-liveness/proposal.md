# Сторож метабазы отличает живого владельца сессии от брошенной

## Why

В снимке от 2026-09-02 одна находка: сессия метабазы в `idle in transaction` двадцать
четыре часа, сервер ждёт клиента, блокировок нет. Владелец опознан — таск чужого дага.
И на этом отчёт заканчивается: по нему нельзя понять, идёт ли эта таска до сих пор или
процесс давно умер, а соединение осталось. Диагнозы разные — в первом случае вопрос к
владельцам дага, во втором сессию надо просто закрыть.

Разница важна не только для чтения. Открытая транзакция держит `xmin`, и autovacuum не
чистит мёртвые версии по всей базе — распухает то же самое, с чем борется чистильщик
метабазы. Само собой это не рассосётся: таймауты сессии метабазе намеренно не ставятся
из кода (отказ на `connect` дороже долгой транзакции), а серверного
`idle_in_transaction_session_timeout` на ней, судя по находке, нет.

Отдельно опасен нынешний отбор кандидатов на прекращение: под него подходит любая
зависшая транзакция или долгий запрос, кроме собственных, — то есть при включённой галке
сторож может уронить живую чужую задачу.

## What Changes

- Находка несёт состояние владельца: задача, её состояние и свежесть хартбита. «Владельца
  не опознали» и «владелец мёртв» — разные ответы, а не общий пустой список.
- Владелец считается живым, если его задача выполняется и хартбит не старше порога;
  порог по умолчанию совпадает с зомби-детектором Airflow, чтобы вердикты не расходились.
- **BREAKING**: кандидатом на прекращение становится только сессия без живого владельца.
  Живую чужую задачу сторож не роняет ни при каких настройках.
- В сводке появляется счётчик находок без живого владельца, а возраст транзакции пишется
  по-человечески: суточная не должна теряться среди пятиминутных.

## Capabilities

### New Capabilities

Новых capability нет.

### Modified Capabilities

- `check`: находка сторожа метабазы несёт состояние владельца; прекращение сессий
  допускается только для сессий без живого владельца.

## Impact

- Спецификация: `check`
- Код: `check/pg_activity.py`
- Конфигурация: новый параметр `zombie_after_sec` в форме и в Variable `tools_pg_activity_cfg`
- Документация: `check/readme.md`
