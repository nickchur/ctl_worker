# 🚀 Быстрый старт: заводим выгрузку в ЕР

*2026-08-28 14:30 MSK · v1.0 · Чуркин Николай · [nschurkin@sber.ru](mailto:nschurkin@sber.ru)*

Пошагово, с готовыми текстами для копирования. Подробности — в [README.md](README.md);
сюда вынесено то, что нужно, чтобы довести первую выгрузку до зелёного рана.

## Три понятия

| Слово | Что значит |
| :--- | :--- |
| **поставка** | одна таблица: свой SQL, свой состав колонок, своё состояние дельты |
| **группа (пакет)** | набор поставок, которые уезжают вместе: один DAG, одно расписание, один тикет для ЕР. Задаётся парой колонок `replica` + `dag_group`, даг называется `export_er__<replica>__<dag_group>` |
| **строка-дефолт группы** | строка настройки с пустым `extract_name`: расписание и общие параметры пакета. **Обязательна** |

Всё живёт в таблице `export.er_wf_meta` (ClickHouse), а правится DAG-ом
**`export_er_setup`** — руками в таблицу ходить не нужно.

## Шаг 1. Завести группу

Запускаем `export_er_setup`, во второй группе полей формы:

* **Поток** → `➕ новая запись`
* **Патч**:

```json
{
  "replica": "hrplatform_datalab",
  "dag_group": "7",
  "description": "Пакет 7: мой первый",
  "params": "{\"schedule\": \"30 2 * * *\", \"notify_kafka\": 0, \"auto_confirm\": 1}"
}
```

Что здесь важно:

* `extract_name` и `schema_name` пусты — **это и есть** признак строки-дефолта, других нет;
* `schedule` лежит **внутри `params`** и только у этой строки. У поставки он игнорируется;
* `notify_kafka: 0` и `auto_confirm: 1` на первое время: пакет соберётся, но в ТФС
  ничего не уедет и ждать квитанций никто не будет. Включите их, когда выгрузка поедет
  как надо;
* `dag_group` — номер (или имя) группы. Пусто — синхронизация подставит `0`.
  Даг будет называться `export_er__hrplatform_datalab__7`.

## Шаг 2. Завести поставку

Тот же DAG, **Поток** → `➕ новая запись`, **Патч**:

```json
{
  "replica": "hrplatform_datalab",
  "dag_group": "7",
  "schema_name": "learning",
  "extract_name": "lc_items_meta",
  "uk": ["item_id"],
  "fields": ["item_id", "title", "insert_time"],
  "sql_from": "evolution.lc_items_meta",
  "params": "{\"time_field\": \"insert_time\"}"
}
```

* `fields` — **явный список, обязателен**. `*` и `t1.*` запрещены: иначе новая колонка
  источника уехала бы в КАП сама, без единой правки настройки;
* `schema_name` — целевая схема на стороне ЕР; она входит в ключ, не наследуется
  и обязательна у каждой поставки;
* базу источника отдельным полем писать не нужно: она берётся из `sql_from`, поэтому
  там пишем `db.table`;
* `time_field` — колонка, по которой строится окно дельты (по умолчанию `insert_time`);
* окно в `sql_where` писать не надо, фабрика допишет его сама.

## Шаг 3. Посмотреть и проверить

**Поток** → ключ записи (`hrplatform_datalab/7/learning/lc_items_meta`), **Патч** оставить пустым.

Это просмотр: запись показывается, её запрос собирается тем же кодом, что и в выгрузке,
и выполняется с `LIMIT 0` — данные не читаются, но ошибки в SQL и расхождение `fields`
с источником видны сразу. В таблицу при этом ничего не пишется.

Красный `check` — читайте текст ошибки целиком, там обычно готовый рецепт (например,
предложение добавить алиас в `fields`).

## Шаг 4. Синхронизировать

Любой ран `export_er_setup` заканчивается таском `sync` — он раскладывает таблицу по
группам в Variable `datalab_er_wfs`, откуда фабрика поднимает DAG-и. Если ничего
не менялось, `sync` уходит в ☮️ — это нормально.

Красный `sync` = ошибка настройки. Причины в заметке, полный список в логе и в XCom
`errors`. **Ошибка ломает группу целиком**, а не одну поставку: тикет в ЕР один на пакет,
и уехать неполным составом он не должен.

## Шаг 5. Запустить пакет

DAG `export_er__hrplatform_datalab__7` создаётся **на паузе** — снимите её и запустите
руками (Trigger DAG). Если в строке-дефолте стоит `is_paused = 1`, синхронизация будет
возвращать паузу на каждом прогоне: сначала снимите флаг в настройке.

Что происходит внутри:

| Таск | Что делает | Куда смотреть |
| :--- | :--- | :--- |
| `make_ts` | метка времени пакета — от неё строятся имена всех файлов | заметка таска |
| `<таблица>.init` | считает окно дельты | заметка `⚙️ Delta State` |
| `<таблица>.build_meta` | собирает `.meta` и сверяет колонки с `fields` | заметка со списком колонок |
| `<таблица>.export_to_s3` | выгружает данные в S3 | лог оператора |
| `<таблица>.pack_zip` | пакует в ZIP формата ЕР | заметка с именами архивов |
| `make_summary` | общий тикет пакета, постановка файлов в очередь отправки | заметка `🧾` |
| `wait_confirm` | ждёт квитанции ТФС (☮️ при `auto_confirm=1`) | заметка `📨 TFS confirm` |
| `save_status` | пишет результат в `export.extract_history` | заметка `💾` |
| `schedule_next` | взводит следующий цикл, если дельта отстала | заметка `⏭️` |

Файлы лежат в `s3://tfshrplt/from/KAP802/hrpl_lm_er/`, очередь отправки и квитанции —
в тракте `tfs_kafka` (см. [../tfs_kafka/README.md](../tfs_kafka/README.md)).

## Готовые шаблоны

### Поставка с JOIN

Алиасы обязательны: при двух и более JOIN-ах ClickHouse оставляет в имени колонки
квалификатор таблицы, и точка уедет в заголовок файла и в `.meta`.

```json
{
  "replica": "hrplatform_datalab",
  "dag_group": "7",
  "schema_name": "learning",
  "extract_name": "lc_items_opened",
  "uk": ["person_uuid", "item_id"],
  "fields": ["t1.person_uuid AS person_uuid", "t1.item_id AS item_id",
             "t2.flag AS flag", "t1.insert_time AS insert_time"],
  "sql_from": "evolution.lc_items_opened t1",
  "sql_join": "LEFT JOIN evolution_export.lc_items_opened_exp t2 ON t1.item_id = t2.item_id",
  "params": "{\"time_field\": \"t1.insert_time\"}"
}
```

### Таблица без поля времени — выгружаем целиком

```json
{
  "replica": "hrplatform_datalab",
  "dag_group": "7",
  "schema_name": "learning",
  "extract_name": "dict_regions",
  "uk": ["region_id"],
  "fields": ["region_id", "name"],
  "sql_from": "evolution.dict_regions",
  "params": "{\"full_export\": 1, \"time_field\": \"\"}"
}
```

### Скользящее окно вместо дельты (recent)

```json
{
  "replica": "hrplatform_datalab",
  "dag_group": "7",
  "schema_name": "learning",
  "extract_name": "lc_progress",
  "uk": ["person_uuid"],
  "fields": ["person_uuid", "pct", "insert_time"],
  "sql_from": "evolution.lc_progress",
  "params": "{\"is_recent\": 1, \"recent_interval\": 120}"
}
```

### Та же таблица во второй группе (новая версия пакета)

Заводим вторую строку-дефолт с другим `dag_group` и повторяем поставку в ней. Состояние
дельты у групп разное — в истории имя выгрузки составное, `<dag_id>.<extract_name>`.

```json
{"replica": "hrplatform_datalab", "dag_group": "8", "params": "{\"schedule\": \"0 5 * * *\"}"}
```

### Выгрузка построчным JSON

```json
{"params": "{\"format\": \"JSONEachRow\"}"}
```

### Правки существующей записи

```json
{"is_active": 0}                                     // убрать из пакета (у группы — весь пакет)
{"is_paused": 1}                                     // мягко: таск скипается, даг на паузе
{"fields": ["item_id", "title", "tags", "insert_time"]}   // поменять состав колонок
{"params": "{\"schedule\": \"0 5 * * *\", \"notify_kafka\": 1}"}   // расписание группы
```

> ⚠️ `params` патчится **целиком**: перечисляйте в нём все нужные ключи, а не только
> изменившийся. Посмотреть текущее значение — просмотром (пустой патч).

**Чем `is_paused` отличается от `is_active = 0`:**

| | группа | поставка |
| :--- | :--- | :--- |
| `is_active = 0` | дага нет вовсе | таска нет в пакете |
| `is_paused = 1` | даг есть, но на паузе | таск есть, но скипается; включается галкой в форме запуска |

Паузу группы синхронизация **дожимает** на каждом прогоне и обратно не снимает: чтобы
запустить пакет, сначала уберите `is_paused` в настройке.

## Частые ошибки

| Что видно | Почему | Что делать |
| :--- | :--- | :--- |
| `нет строки-дефолта` | поставку завели раньше группы | завести строку-дефолт (шаг 1) |
| `у строки-дефолта заполнен schema_name` | схема входит в ключ | очистить её у дефолта, оставить только у поставок |
| таск скипается сам | у поставки `is_paused = 1` | включить галкой на один ран или снять флаг в настройке |
| даг снова на паузе после синка | у группы `is_paused = 1` | снять флаг в строке-дефолте |
| `не задано расписание` | в `params` строки-дефолта нет `schedule` | добавить `{"params": "{\"schedule\": \"30 2 * * *\"}"}` |
| `расписание … не cron и не пресет` | опечатка в cron | проверить пятью полями: `мин час день месяц день_недели` |
| `Эти поля больше не колонки таблицы` | пишете `schedule`/`is_recent` колонкой | перенести в `params` |
| `fields должен быть явным списком` | `*` или `t1.*` | перечислить колонки |
| `Состав колонок … разошёлся с настройкой fields` | источник изменился или нет алиаса | поправить `fields`; при точке в имени — добавить `AS` |
| `пустой schema_name` | у поставки не указана целевая схема | заполнить `schema_name` — он в ключе и не наследуется |
| `содержит '__'` | двойное подчёркивание в `replica`, `dag_group`, `schema_name` или `extract_name` | убрать: это разделитель в именах файлов ЕР, лишний сдвинет разбор на стороне КАП |
| `содержит […]` / `допустимы только буквы, цифры` | точка, слэш, пробел или кавычка в имени | оставить только `[A-Za-z0-9_-]`: точка и слэш разделяют части ключей, кавычка ломает SQL |
| `.meta` без описаний колонок | в `sql_from` имя без базы | писать `db.table`, базы отдельного поля больше нет |
| `Не найдены Airflow connection` | нет коннекта на стенде | завести `dlab-click` / `s3-tfs-hrplt` |
| пакет собрался, но пуст | окно дельты пустое | это норма; слать пустые — `{"params": "{\"send_empty\": 1}"}` |
| `Квитанции ТФС не пришли` | файлы стоят в очереди либо ТФС молчит | смотреть `tfs_kafka_snd` и `tfs_kafka_rcv` |
| правка настроек «не применилась» | общие настройки читаются на разборе файла | подождать ~30 секунд и повторить |

## Шпаргалка по параметрам

Только то, что трогают чаще всего. Полные списки — в README, разделы «Групповые» и
«Табличные».

| Ключ `params` | Умолчание | Смысл |
| :--- | :--- | :--- |
| `schedule` | — | cron пакета. **Только в строке-дефолте**, обязателен |
| `is_recent` | `0` | `1` = скользящее окно вместо дельты |
| `notify_kafka` | `1` | слать ли уведомление в ТФС |
| `auto_confirm` | `1` | `1` = не ждать квитанцию |
| `confirm_timeout` | `60` | сколько минут ждать квитанции |
| `max_active_tasks` | `4` | сколько таблиц пакета грузятся разом |
| `full_export` | `0` | `1` = выгружать таблицу целиком |
| `time_field` | `insert_time` | поле времени для окна дельты |
| `increment` | `60` | шаг дельты в минутах |
| `format` | `TSVWithNames` | `TSVWithNames` или `JSONEachRow` |
| `send_empty` | `0` | `1` = слать пустой пакет при нулевой дельте |
| `strategy` | `FULL_UK` | стратегия слияния на стороне ЕР |

Групповые ключи (`schedule`, `notify_kafka`, `auto_confirm`, `confirm_timeout`,
`selfrun_timeout`, `max_active_tasks`) работают только в строке-дефолте: в поставке они
игнорируются с предупреждением. Табличные наследуются от группы и переопределяются
в поставке.
