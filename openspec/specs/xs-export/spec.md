# xs-export Specification

## Purpose

Выгрузки xStream: DAG'и на каждую из выгрузок генерируются из файла метаданных, а не пишутся
руками. Каталог держит фабрику DAG'ов, общую библиотеку задач и сами метаданные. Спецификация
намеренно короткая — она описывает рамки, а подробности дописываются тем, кто первым будет
менять этот каталог.

## Requirements

### Requirement: DAG'и собираются из файла метаданных

Система SHALL создавать по одному DAG'у на каждую запись файла метаданных выгрузок, собирая
SQL-запросы из описания таблицы и специфичных частей записи (соединения, условия, настройки).
Добавление выгрузки MUST NOT требовать правки кода.

#### Scenario: Новая выгрузка

- **WHEN** в файл метаданных добавлена запись
- **THEN** после разбора DAG-файла в Airflow появляется соответствующий DAG

#### Scenario: Расписание не указано

- **WHEN** у записи нет расписания
- **THEN** DAG получает ежедневное расписание по умолчанию

### Requirement: Единый набор тегов

Каждый сгенерированный DAG SHALL получать общий набор тегов каталога, по которому выгрузки
xStream отличимы в интерфейсе от остальных DAG'ов контура.

#### Scenario: Отбор выгрузок в UI

- **WHEN** пользователь фильтрует DAG'и по тегу xStream
- **THEN** видны все сгенерированные выгрузки и только они

### Requirement: Общие задачи вынесены в библиотеку

Повторяющаяся часть выгрузки SHALL собираться общей функцией построения группы задач, а не
копироваться в каждый DAG. Импорт этой библиотеки SHALL переживать разные расположения
каталога на контурах.

#### Scenario: Каталог лежит по другому пути на боевом контуре

- **WHEN** модуль импортируется там, где библиотека доступна под другим именем пакета
- **THEN** импорт проходит по запасному пути, DAG'и собираются как обычно
