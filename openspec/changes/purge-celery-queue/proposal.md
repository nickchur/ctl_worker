# Чистка очереди celery от сообщений без задач

## Why

Очередь `default` на альфе держит ~950 сообщений при 16 задачах, которые Airflow
действительно считает отданными celery. Остальное — сообщения, за которыми задач уже нет:
при `task_acks_late = True` неподтверждённое сообщение возвращается в очередь через
`visibility_timeout` (6 ч) и ходит по кругу, а его задача давно завершилась или была
очищена. Замер на контуре: из 914 сообщений живыми оказались ~27, а из 254 строк
`celery_taskmeta` в статусе `STARTED` у 245 не было `task_instance` вообще.

Убрать это можно только из пода: брокер снаружи недоступен, а прав на `kubectl` у
дежурного нет. Разовый скрипт, заносимый в под heredoc'ом, требует ровно тех прав,
которых нет, и оставляет дамп удалённого в `/tmp` — то есть до первого перезапуска пода.

## What Changes

- Новый DAG `tools_queue_cleanup` в `check/`: инвентаризация очередей celery, разметка
  каждого сообщения на живое и мусорное по метабазе, точечное удаление мусора.
- Удаление включается отдельным флагом запуска, по умолчанию идёт подсчёт. Флаг **не**
  сохраняется в Variable вместе с остальными параметрами.
- Дамп удаляемого уезжает в S3, а не в `/tmp` пода: из него сообщение возвращается
  `rpush`, и он же остаётся следом для разбора.
- Расписания у DAG нет: это инструмент разбора, а не регулярная чистка.

## Capabilities

### New Capabilities

Новых нет.

### Modified Capabilities

- `check`: добавляются требования к чистке очереди брокера — разметка по задаче, названной
  в сообщении, обязательная сверка ключей redis до удаления, защита от неосторожного
  запуска и возвратный дамп удаляемого.

## Impact

- `check/queue_cleanup.py` — новый DAG.
- `check/readme.md` — описание инструмента.
- Внешние системы: брокер celery (redis) — единственное место, где DAG меняет состояние;
  метабаза Airflow — только чтение; S3 (бакет логов задач, своя папка) — запись дампа.
- Прав на `kubectl` не требует: всё делается изнутри пода средствами Airflow.
